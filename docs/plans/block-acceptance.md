## Контрольные точки

1. PB-065 фиксирует окончательные поля, версии схем и CLI; нельзя менять только start без общей семантики графа.
2. PB-066 подтверждает три варианта приёмки на fixtures. Реальные текущие задачи не мигрируются.
3. PB-067 подтверждает финальный candidate и revalidate ранних критериев после поздних правок; исторические handoff не переписываются.
4. PB-068 сохраняет findings/fix obligations атомарно и не пишет в архив.
5. PB-069 доказывает полную общую приёмку, close, прерывание и restore на временных проектах.
6. PB-070 документирует принятые интерфейсы и opt-in; PB-071 воспроизводит полный пользовательский путь.
7. AUDIT-010 проводится независимой сессией/инженером, не исполнителем блока; приёмка и закрытие только с необходимыми полномочиями.

## Проверки и доказательства

Каждая реализация добавляет постоянные позитивные/негативные тесты своих критериев и подходящую регрессию, проходит актуальные preflight/verify, оформляет EXEC/CHECK/HANDOFF и отдельную приёмку. Конкретные команды воспроизведения фиксируются в передаче; имена будущих тестовых модулей не считаются существующими командами.

PB-071 ведёт матрицу AC-01–12: сценарий, команда, ожидаемое/фактическое, код выхода, отчёт, candidate. Обязательны subprocess CLI на временных проектах, контроль хешей архива и fault injection; никаких фиктивных accepted для самопроверки рабочей задачи. index/check --ready — только структура. Полный verify — по действующему контракту и лимитам, без параллельной записи lifecycle.

Общие доказательства принадлежат AUDIT-010; локальные — своим карточкам. Общие документы не архивируются при закрытии отдельного этапа. Self-manifest обновлять при изменении файлов комплекта. Нынешняя подготовка затрагивает только docs и индексы, поэтому не меняет self-manifest.

## Зависимости, запуск и ограничения

Перед стартом согласовать spec/design/ADR/план и разрешить PB-065. Для каждого этапа: актуальный card show/handoff пересекающихся работ, завершённые строгие зависимости, назначение исполнителя, сохранение чужих незакоммиченных правок. PB-041/PB-046–050 и PB-057–064 пересекаются с lifecycle/metadata/verification; использовать реально принятый API, новые зависимости добавлять явно.

Новые runtime-настройки и автоматический запуск агентов не входят в подготовку. Новый порядок не отменяет разрешения инженера на выполнение, независимую приёмку, закрытие и отдельные Git-действия.
