## A-02 остаётся открытым — P2 — Перезапись исходного состояния предка

Критерии: AC-03. Источник: checks_inventory.py:351.

snapshot получает directory-входы missing/x и src/payments, затем file-вход missing/y. Изначально missing отсутствует. hash_fn файлов src/payments создаёт пустой missing. Поздний resolve(missing/y) заменяет watch_states[missing] с absent на dir. Финальная сверка не замечает изменение: функция успешно возвращает снимок, хотя появление отсутствовавшего предка по критерию A-02 должно быть отклонено.

Исправление: сохранять первое наблюдение префикса и отвергать расхождение при последующих наблюдениях; добавить регрессию с общим отсутствующим предком и разными входами. Простого setdefault без сверки недостаточно для раннего выявления изменений, но финальная сверка должна как минимум сравнивать с исходным состоянием.

## A-05 — P2 — Гонка в исключённом поддереве обходится без коллизии

Критерии: AC-02, AC-03. Источник: checks_inventory.py:361–381,408–418,523–525.

Валидная политика: module.paths=[src/payments/**/*.py], excludes=src/**/gen. Сначала gen пуст. excluded_holds_input проверяет его и разрешает пропуск. При последующем хешировании pay.py hash_fn создаёт gen/out.py. snapshot успешно возвращается без out.py; финальная сверка игнорирует gen и не перепроверяет коллизию. Повторный обычный snapshot того же дерева уже отвергает конфликт.

Влияние: успешный снимок пропускает новый вход, пересекающийся с исключением; нарушены R-07 и контроль изменяющегося дерева.
Исправление: наблюдать состав проверенных исключённых поддеревьев либо повторно проверять их устойчивость/коллизии в конце. Регрессия должна создавать совпадающий файл после первоначального обхода и получать контролируемый отказ.

## A-06 — P1 — Перекрывающийся path-вход стирает контроль изменения байтов

Критерии: AC-01, AC-03. Источник: checks_inventory.py:455–458 (ветка rel in anys; присваивание watch_files до hash_file).

Валидный check.inputs=[src/payments, src/payments/pay.py], module.paths=[src/payments/**]. Во время хеширования каталога hash_fn читает pay.py='old', затем меняет его на 'mutated longer'. Поздняя обработка строкового path-входа pay.py перезаписывает watch_files новыми size/mtime, но hash_file возвращает кешированный старый SHA-256 без повторного чтения. Финальная сверка проходит. Оба entries содержат SHA-256 old, фактический файл имеет другой SHA-256.

Влияние: явное изменение байтов во время снимка не отклоняется, снимок не соответствует кандидату. Возможна ложная свежесть при потреблении снимка будущим runner.
Исправление: сохранять метаданные первого хеширования и не перезаписывать их при перекрывающихся входах; изменение должно давать отказ при сохранении одного хеширования на файл. Добавить регрессию directory+string-path с мутацией файла после первого хеша.
