## Задача

### Цель и границы

Снимки и исключения. Новый inventory/snapshot слой и интеграция с verification_policy/project_view; изолированные файловые fixtures. Не переписывать незавершённый engine PB-046.

### Контекст

[Спецификация](../specs/dependency-aware-verification.md): R-05–07,15; сценарии AC-02–03,07. [Design](../designs/dependency-aware-verification.md), [ADR-0006](../adr/0006-dependency-aware-verification.md), [план](../plans/dependency-aware-verification.md).

Подготовлено по поручению инженера 2026-11-07. Выполнение пока не разрешено. Перед стартом: принятие технического проекта, завершённые зависимости, актуальный card show/handoff затрагиваемых работ и назначение исполнителя. Исходные чужие изменения сохранять.

### Критерии приёмки

- [ ] AC-01: Inventory без .git обнаруживает add/delete/rename, одинаковые mtime/size с другими байтами, absent inputs, неизвестные пути и ошибки чтения; потоковое хеширование одного файла один раз на снимок.
- [ ] AC-02: Исключения имеют причину, конфликт с нужным входом отклоняется; служебные каталоги не читаются массово, используемые ресурсы не теряются. Symlink escape и циклы безопасно отклоняются.
- [ ] AC-03: Содержательные требования и служебные поля карточки разделены; snapshot входов не смешивается с lifecycle snapshot. Гонки и повреждённые/утраченные snapshots не дают reused.
- [x] AC-04: Целевые поведенческие проверки и связанные регрессии пройдены; документация и self-manifest актуальны, EXEC/CHECK/HANDOFF содержат реальные доказательства и ограничения; передача зарегистрирована штатным CLI.

### План

1. Уточнить фактические интерфейсы зависимостей и связать изменения с критериями этой карточки.
2. Реализовать ограниченный объём, добавить постоянные позитивные и негативные проверки критериев AC-01–03; не подменять их структурной проверкой.
3. Обновить затронутые документы/шаблоны и self-manifest при изменениях комплекта; выполнить адресные проверки, index и check --ready.
4. Подготовить материалы и пройти действующие preflight/verify/handoff. До явного opt-in использовать прежний контракт; не отключать полный legacy suite ради экономии.
5. Записать EXEC/CHECK/HANDOFF и передать независимому аудитору; самостоятельно не закрывать.

### Ресурсы

Python и стандартная библиотека для основного CLI; локальные временные проекты и subprocess-счётчики. Новые зависимости защищённого executor обосновать в рамках принятого design. Фактические среда, policy_revision и бюджет фиксируются при старте; доступность отдельной OS/CI identity не предполагается.

Материалы: `docs/tasks/PB-058-evidence/`; команды воспроизведения и отчёты принадлежат этой карточке. Общие материалы и сквозная матрица — AUDIT-009/PB-064.

#### A-01 — Замечание
Серьёзность: P1
Критерии: AC-01, AC-03
Проблема: _group_inputs сужает явный строковый вход каталога модульным фильтром того же пути (checks_inventory.py:293–294).
Воспроизведение: проба A; check.inputs=["src/payments"], module.paths=["src/payments/*.py"]; изменить notes.md.
Факт: SHA-256 notes.md отсутствует; diff возвращает complete=true, fresh=true, changed=[].
Влияние: изменение байтов явно объявленного входа теряется и допускает ложную свежесть.
Критерий исправления: объединение входов сохраняет полный охват явного каталога; регрессия обнаруживает изменение notes.md.

#### A-02 — Замечание
Серьёзность: P2
Критерии: AC-03
Проблема: отсутствующие входы не включаются в финальную проверку гонок (checks_inventory.py:392–393,412–413).
Воспроизведение: проба B; после наблюдения a-missing как absent создать его в hash_fn другого входа.
Факт: snapshot успешно возвращает absent для уже существующего файла.
Влияние: снимок не соответствует текущему дереву без предупреждения об изменении.
Критерий исправления: финальная сверка отслеживает отсутствие файлов/каталогов и отсутствующих предков; появление входа вызывает отказ либо согласованное повторное построение.

#### A-03 — Замечание
Серьёзность: P2
Критерии: AC-01
Проблема: resolved_inputs безусловно превращает литеральный путь модуля в directory (checks_inventory.py:227–231).
Воспроизведение: проба C; module.paths=["src/payments/pay.py"], файл существует; resolved_inputs → snapshot.
Факт: отказ «вход 'src/payments/pay.py' не является каталогом» при валидной политике.
Влияние: модуль из конкретного файла не поддерживается вопреки контракту paths.
Критерий исправления: литеральные файлы корректно разрешаются и хешируются; добавить сквозную регрессию.

#### A-04 — Замечание
Серьёзность: P2
Критерии: AC-02
Проблема: snapshot отклоняет исключённый файл вне фильтра модульного входа (checks_inventory.py:355–358).
Воспроизведение: проба D; module.paths=["src/payments/*.py"], excludes=src/**/fixtures.bin, check.inputs отсутствует; создать fixtures.bin.
Факт: validate_policy и inventory успешны, snapshot падает с конфликтом исключения.
Влияние: допустимое селективное исключение блокирует снимок, даже когда файл не входит в выбранный glob.
Критерий исправления: исключения вне выбранных входов пропускаются; реальные коллизии с явными входами отклоняются; добавить совместную регрессию policy → inventory → resolved_inputs → snapshot.
