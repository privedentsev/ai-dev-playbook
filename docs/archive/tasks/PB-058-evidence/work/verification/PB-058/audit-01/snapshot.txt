## Задача

### Цель и границы

Снимки и исключения. Новый inventory/snapshot слой и интеграция с verification_policy/project_view; изолированные файловые fixtures. Не переписывать незавершённый engine PB-046.

### Контекст

[Спецификация](../specs/dependency-aware-verification.md): R-05–07,15; сценарии AC-02–03,07. [Design](../designs/dependency-aware-verification.md), [ADR-0006](../adr/0006-dependency-aware-verification.md), [план](../plans/dependency-aware-verification.md).

Подготовлено по поручению инженера 2026-11-07. Выполнение пока не разрешено. Перед стартом: принятие технического проекта, завершённые зависимости, актуальный card show/handoff затрагиваемых работ и назначение исполнителя. Исходные чужие изменения сохранять.

### Критерии приёмки

- [x] AC-01: Inventory без .git обнаруживает add/delete/rename, одинаковые mtime/size с другими байтами, absent inputs, неизвестные пути и ошибки чтения; потоковое хеширование одного файла один раз на снимок.
- [x] AC-02: Исключения имеют причину, конфликт с нужным входом отклоняется; служебные каталоги не читаются массово, используемые ресурсы не теряются. Symlink escape и циклы безопасно отклоняются.
- [x] AC-03: Содержательные требования и служебные поля карточки разделены; snapshot входов не смешивается с lifecycle snapshot. Гонки и повреждённые/утраченные snapshots не дают reused.
- [x] AC-04: Целевые поведенческие проверки и связанные регрессии пройдены; документация и self-manifest актуальны, EXEC/CHECK/HANDOFF содержат реальные доказательства и ограничения; передача зарегистрирована штатным CLI.

### План

1. Уточнить фактические интерфейсы зависимостей и связать изменения с критериями этой карточки.
2. Реализовать ограниченный объём, добавить постоянные позитивные и негативные проверки критериев AC-01–03; не подменять их структурной проверкой.
3. Обновить затронутые документы/шаблоны и self-manifest при изменениях комплекта; выполнить адресные проверки, index и check --ready.
4. Подготовить материалы и пройти действующие preflight/verify/handoff. До явного opt-in использовать прежний контракт; не отключать полный legacy suite ради экономии.
5. Записать EXEC/CHECK/HANDOFF и передать независимому аудитору; самостоятельно не закрывать.

### Ресурсы

Python и стандартная библиотека для основного CLI; локальные временные проекты и subprocess-счётчики. Новые зависимости защищённого executor обосновать в рамках принятого design. Фактические среда, policy_revision и бюджет фиксируются при старте; доступность отдельной OS/CI identity не предполагается.

Изменения: новый модуль checks_inventory.py — файловый слой выбора проверок без Git по design §4 и spec R-05–07,15. `build_inventory` обходит проект без чтения байтов: классификация путей по glob модулей политики, unknown_paths, исключённые пути с причиной и origin; одобренные excludes применяются к дереву, служебные .git/work/__pycache__/.pytest_cache/.DS_Store не читаются массово. Symlink любого вида (escape, цикл, внутри входа), специальные файлы, циклические каталоги и ошибки чтения — отказ. Обнаруженная коллизия исключения с объявленным входом check.inputs — ошибка. `snapshot` хеширует только объявленные и вычисленные входы (`resolved_inputs`: check.inputs + области модулей с фильтром образца): потоковый SHA-256 через project_view.digest_file, один путь один раз на снимок, absent фиксируется, каталог хранит полный состав потомков. После снятия все наблюдавшиеся файлы и каталоги сверяются повторно — изменившееся дерево отклоняется. Снимок checks-input-snapshot schema_version 1 — отдельный формат от lifecycle snapshot; task/policy проекции берутся из verification_policy (служебные поля карточки не влияют на отпечаток). diff_snapshots/diff_inventories различают add/delete/rename и смену байтов при равных mtime/size; утраченный/повреждённый/чужой baseline — complete=false. Валидаторы форматов и snapshot_compatible для привязки к policy_digest. Engine PB-046 и verification_policy/project_view не переписаны; режим в self-project не включён.
