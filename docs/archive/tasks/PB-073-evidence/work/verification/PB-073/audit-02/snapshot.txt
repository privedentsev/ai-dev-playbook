## Задача

### Цель и границы

Устранить A-01–A-03 независимого аудита AUDIT-009: потерю обязательств задачи после неуспешного прогона, выбор старого passed при равном finished_at и невозможность воспроизвести self-pilot после архивирования PB-064. Сохранить legacy/opt-in, честные границы local/protected и корректный cross-task reuse. Архивные карточки и доказательства не переоткрывать и не переписывать; исправления пилота оформить новым активным материалом/инструментом. Реализация выполнена, передана на независимый повторный аудит AUDIT-009.

[AUDIT-009](AUDIT-009.md), [независимый протокол с A-01–A-03](AUDIT-009-evidence/audit-01.md), [команды и результаты](AUDIT-009-evidence/commands.json). Требования: [R-08–12, R-15–16 и AC-05,09,11](../specs/dependency-aware-verification.md); [design §5–6,10](../designs/dependency-aware-verification.md).

Источники реализации: [PB-059](../archive/tasks/PB-059.md), [PB-060](../archive/tasks/PB-060.md), [PB-062](../archive/tasks/PB-062.md), [PB-064](../archive/tasks/PB-064.md). ### Критерии приёмки

- [ ] AC-01: Обязательства задачи сохраняются до подтверждённого покрытия: failed/timeout/blocked и неподтверждённая ручная проверка не исчезают из-за обновления общего baseline. Реальный CLI во временном проекте без Git не превращает failed в not_applicable/успех при повторном stale; task gate/handoff остаются закрыты. Проверены новая попытка после исправления, запуск другой задачи и законный reuse, без подмены задачи always-применимостью в регрессии.
- [x] AC-02: Для локальной append-only истории определён устойчивый порядок исходных исполнений при одинаковом finished_at; load/index/rebuild/selector/runner/gate используют согласованный выбор. Более поздний failed/timeout не маскируется старым passed; последующий успешный фактический запуск восстанавливает покрытие. Проверены оба лексикографических порядка run IDs, cross-task результаты и сохранение времени/provenance при reuse; protected-порядок не ухудшен.
- [x] AC-03: Предоставлен новый воспроизводимый self-pilot, работающий из текущего репозитория после архивирования PB-064 без изменений архива. Plan-only проходит; полный сценарий на временных копиях измеряет команды, файлы/байты и время и сохраняет команды/исходы. Ссылки и инструкции указывают на доступные пути, локальная диагностика отделена от доказанного protected; основные project.json/checks_policy не включаются автоматически.

#### A-01 — Замечание

Серьёзность: P1
Критерии: AC-01
Проблема: сохранение baseline только при ok недостаточно: если baseline уже актуален, новый failed не создаёт diff, и task selector игнорирует непокрытое обязательство.
Воспроизведение: запустить приложенный probe_baseline_failure.py из корня; project force passed → project force failed → task stale и task gate, без правок входов и без applicability=always.
Факт: rc последовательности 0 → 1 → 0; исполнений 2; task stale не исполняет payment; task gate ok=true, payment=not_applicable при последнем failed. checks_runner.py:553–561 и checks_select.py:589–596.
Влияние: задача получает ложное успешное покрытие после неуспешного запуска; AC-01/R-11/R-16 не выполнены.
Критерий исправления: обязательство остаётся непокрытым до нового успешного доказательства независимо от diff; task stale повторно исполняет payment, task gate закрыт. Добавить постоянную CLI-регрессию данного сценария и аналоги для timeout/blocked/manual/другой задачи, сохранив законный reuse.
