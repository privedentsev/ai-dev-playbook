# AUDIT-007: протокол независимого аудита

Результат: **changes_requested**. Исполнитель: Codex; модель: GPT-6; дата: 2026-11-06. Независимая сессия аудита блока PB-031–PB-037. Реализация не исправлялась. Успешная приёмка, promotion, закрытие/архивирование блока не выполняются из-за находок.

## AUDIT-007-A1 — P1: изменение среды не инвалидирует результат v2

Критерии: AC-08, AC-09; требования R-19, R-20. Владелец исправления: PB-033.

`verification.py:677–683` фиксирует только os/platform/python/architecture. В отличие от legacy `runtime_identity`, здесь нет отпечатка переменных окружения и пути интерпретатора. `_find_v2_reusable_results` сравнивает этот неполный набор, хотя subprocess наследует реальное `os.environ`.

Воспроизведение: [probe.py](probe.py), сценарий environment-reuse. Разрешённая команда завершается 0 при `AUDIT007_MODE=pass`, 9 при `fail`. Первый verify с pass запускает команду; после смены только этой переменной второй verify печатает REUSE и возвращает passed без запуска. Далее handoff, engineer acceptance и close --dry-run возвращают 0. Контрольный verify --no-reuse при том же fail возвращает failed, exit_code=9. Никакие отчёты или источники между этими шагами не подменяются.

Доказательства: [команды](probes/environment-reuse/commands.json), [ложный reuse](probes/environment-reuse/03.stdout.log), [handoff](probes/environment-reuse/04.stdout.log), [accept](probes/environment-reuse/05.stdout.log), [close preview](probes/environment-reuse/06.stdout.log), [контроль](probes/environment-reuse/07.stdout.log), [сводка](probes/summary.json). Сохранены исходные immutable reports.

Влияние: результаты команд, зависящих от среды (флаги тестов, поиск зависимостей и т. п.), могут быть приняты при фактически проваливающейся текущей среде.

Критерий исправления: связывать command-result с реальной существенной средой до/после и при reuse/передаче; хранить отпечатки без значений секретов. При неизвестной независимости инвалидировать результат консервативно. Добавить subprocess-регрессию: смена среды не даёт reuse/приёмку до успешной актуальной проверки; неизменная среда сохраняет reuse; служебный gate не создаёт ложной инвалидизации.

## AUDIT-007-A2 — P2: изменение независимой команды повторяет остальные проверки

Критерии: AC-09; R-19; design §2.4: изменение одного независимого check не требует перезапуска остальных при доказанной неизменности их определения/входов. Владелец: PB-033.

`verification.py:726–727,773–778` привязывает каждый reused result к хешу всего task_workflow, включая определения всех команд. Частичная `policy_projection(..., [registry_id])` уже поддержана чистой политикой, но при сравнении report.policy_hash используется общий отпечаток.

Воспроизведение: два независимых входа src/a.txt и src/b.txt, две команды со счётчиками. Неизменный повтор оставляет 1/1, правка только a — 2/1. Затем меняется исключительно argv команды a; определение, входы, обязательность и среда b прежние. Получено 3/2 вместо 3/1, runner сообщает для b «изменилась политика проверок».

Доказательства: [команды](probes/independent-policy/commands.json), [повтор после argv a](probes/independent-policy/05.stdout.log), [сводка](probes/summary.json). Это избыточный реальный запуск, а не только изменение формата отчёта.

Критерий исправления: отдельно связывать результаты с относящейся к ним политикой/определением, сохраняя повторный расчёт всех обязательств проекта. Смена argv a при доказанной независимости b оставляет b=1; смена обязательности/связанных входов по-прежнему инвалидирует затронутые результаты.

## AUDIT-007-A3 — P2: любой manual-сценарий требует browser

Критерии: AC-05; R-10, R-11. Владелец: PB-033.

`verification.py:997–1002` безусловно понижает passed до not_run, если нет environment.browser. Требование браузера относится к визуальному сценарию; схема kind=manual и спецификация также допускают проверки документации/локального результата без браузера.

Воспроизведение: зарегистрирован terminal-сценарий чтения локального текста, получен текущий candidate_snapshot. Заявление содержит наблюдение, terminal-среду и engineer_confirmation с who/at/statement. CLI возвращает 1 и записывает not_run. Тот же candidate и сценарий с добавлением фиктивного environment.browser принимается как passed.

Доказательства: [команды](probes/manual-terminal/commands.json), [отказ terminal](probes/manual-terminal/04.stdout.log), [контроль с browser](probes/manual-terminal/05.stdout.log), [конфигурация](probes/manual-terminal/project.json). Все заявления синтетические; реальный просмотр/приёмка инженера не утверждаются.

Критерий исправления: проверять требования среды применимого сценария; разрешённый невизуальный manual не требует выдуманного browser, непроведённая визуальная проверка остаётся not_run. Покрыть оба пути регрессиями.

## Положительные результаты и ограничения

- Все семь подзадач на входе имели done и accepted: [состояние и хеши](dependencies.json).
- Проверено 351 перенесённое содержимое, кроме изменяемых карточек/sidecar: все хеши из close companions совпали; [результат](relocation-check.json).
- Свежие subprocess-пробы подтвердили три ручные итерации одного ID, отказы старому candidate/сценарию, ноль автоматических команд manual-only, failed/timeout и stale index, запрет quick acceptance от auditor и закрытия без acceptance. Handoff/accept/close не увеличили счётчики; 14 файлов новых доказательств после архивирования сохранились побайтно.
- [Отдельная recovery-проба](recovery_probe.py): настоящий SIGKILL (-9) после записи карточки во время handoff; пока pending, handoff/accept отклоняются; restore возвращает точные байты карточки/индекса, повтор restore отказывает. Чужой flock блокирует handoff/preflight; после восстановления команда не повторяется. Подмена уже переданного лога блокирует accept/close. [Сводка](recovery/summary.json).
- Матрица остальных AC и соответствующие регрессии — [matrix.md](matrix.md). Результат полного настроенного verify, точный run_id и ограничения его свежести записываются в CHECK карточки AUDIT-007; PASS существующего suite не снимает найденные независимыми пробами дефекты.
- Реального UI нет. Проверка размеров/фокуса/читаемости здесь синтетическая; семантический выбор quick и независимость личности проверяются процессом, не анализом кода или имён. Интеграция с внешним CI не проверяется и не обещается.
- Исходный проект остаётся legacy. Opt-in/update/fault injection выполняются только во временных проектах. Код, конфигурация, manifest и Git-состояние чужих работ не изменялись.

Первый запуск harness остановился на собственном ошибочном восстановлении намеренно испорченного индекса через index: CLI корректно отказал по владению. Harness исправлен: возвращает исходные байты индекса перед index. Исходные логи сохранены в harness-first; это не находка реализации.

Для исправления требуется штатно возобновить PB-033, устранить A1–A3, выполнить проверки и новую передачу, затем провести отдельный повторный аудит подзадачи и блока. Закрытые зависимые подзадачи автоматически не объявляются повторно принятыми на изменённом коде.
