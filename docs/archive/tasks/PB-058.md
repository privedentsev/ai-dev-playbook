### Цель и границы

### Критерии приёмки

- [x] AC-01: Inventory без .git обнаруживает add/delete/rename, одинаковые mtime/size с другими байтами, absent inputs, неизвестные пути и ошибки чтения; потоковое хеширование одного файла один раз на снимок.

Факт: snapshot возвращает старый SHA-256 для обоих входов; фактический файл имеет другой хеш. Поздний path-вход сохраняет новые size/mtime, но использует кеш старого хеша, поэтому финальная сверка проходит.
Влияние: снимок успешно возвращается после явного изменения байтов и не соответствует текущему кандидату; возможна ложная свежесть у потребителя.
Критерий исправления: сохранять метаданные первого хеширования без перезаписи при перекрытии входов; регрессия directory+string-path должна отклонять мутацию при однократном хешировании файла.
