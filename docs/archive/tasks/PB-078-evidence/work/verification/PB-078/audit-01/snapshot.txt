## Задача

### Цель и границы

Устранить A-06 повторного AUDIT-009: поздний failed не должен скрываться старым passed при откате wall clock, если новый run_seq уже свидетельствует о следующем исполнении. Сохранить безопасную обработку legacy, равных меток, повреждённой истории и reuse. Архив PB-057–064/PB-073/PB-074 не менять; реализация в сессии аудита не выполняется.

### Контекст

[AUDIT-009](AUDIT-009.md), [протокол audit-03](AUDIT-009-evidence/audit-03/report.md), [проба](AUDIT-009-evidence/audit-03/probe_clock_rollback.py), [результат](AUDIT-009-evidence/audit-03/clock-rollback.json). Требования: [R-11/R-16, AC-05/AC-09](../specs/dependency-aware-verification.md).

Воспроизведение: `python3 docs/tasks/AUDIT-009-evidence/audit-03/probe_clock_rollback.py .`. Настоящие subprocess-команды, временный проект без Git; время управляется аргументом runner now, часы машины не меняются. Passed/seq=0 → failed/seq=1 при времени на секунду раньше → task/project gate.ok=true; stale reused=1, счётчик остаётся 2. История не редактируется, UUID не подменяются. Причина: checks_select.result_order_key / _latest_better сравнивают finished_at раньше run_seq.

### Критерии приёмки

- [x] AC-01: После последовательных passed → failed/timeout/blocked с большим run_seq, но меньшим finished_at, task/project gate не дают готовность по старому успеху. Status/plan/stale/handoff используют согласованный безопасный расчёт; stale реально перезапускает обязательство либо явно блокирует его. Есть регрессия с subprocess-счётчиком без редактирования истории.
- [x] AC-02: Обработка индекса, утраты записи, rebuild и reuse согласована с выбранным порядком; новый реальный успешный прогон восстанавливает покрытие. Legacy без run_seq, равные метки и конкурентные/перекрывающиеся исполнения не дают старому успеху скрыть недоказанное обязательство. Управление порядком и ограничения явно документированы.
- [x] AC-03: Адресные checks_*/lifecycle-регрессии и штатные index/check/verify проходят, self-manifest обновлён после правок комплекта. Передача содержит новые доказательства, команды и ограничения local/protected; архивные доказательства сохранены. Независимый аудит исправления выполняется отдельно.

### План

1. Прочитать audit-03 и воспроизвести A-06; определить доказуемый порядок истории при несовпадении часов, sequence и параллельных прогонов.
2. Исправить общий выбор и индекс согласованно, добавить поведенческие регрессии; не ослаблять проверки и не скрывать обязательства.

### EXEC-01 — Выполнение
Время: 2026-11-17T02:04:44+03:00
Исполнитель: Devin

Изменения: исправлена A-06 повторного аудита AUDIT-009 — откат wall clock больше не прячет поздний неуспех за старым passed. `checks_select.result_order_key` перестроен в `(run_seq, finished_at, result_id)`: `run_seq` — порядковый номер исходного исполнения прогона, доказанный runner'ом по append-only истории (`next_run_seq`), и старше `finished_at`; `_latest_better` при различном `run_seq` выбирает больший seq независимо от меток времени. При равном `run_seq >= 0` записи принадлежат параллельным прогонам с общим номером — взаимный порядок недоказан, wall clock не доказывает поздний исход, консервативно важнее непокрывающий статус; внутри равного статуса решает `(finished_at, result_id)`. Legacy-пара без `run_seq` (-1) упорядочена `finished_at` как единственным свидетельством, при равной метке — непокрывающий исход (A-05 PB-074 сохранён). То же сравнение едино для selector, производного индекса, его сверки и пересборки: утрата seq-записи теперь обнаруживается индексом независимо от `finished_at`, а rebuild сохраняет свидетельство утраты по seq-порядку. В защищённом контуре `_protected_receipts` выбирает актуальный исход по `(exec_seq, непокрывающий статус, finished_at, result_digest)` — позиция receipt-события в доверенном журнале старше wall clock, семантика aggregate унаследованного порядка сохранена. Статус/plan/stale/handoff используют общий `evidence_latest`/`_latest_better`, поэтому stale реально перезапускает обязательство, а новый фактический passed восстанавливает покрытие. Продуктовые проверки не ослаблены: corrupt_ids, резерв seq индекса и границы local/protected не менялись.
