#### A-01 — Замечание
Серьёзность: P1
Критерии: AC-01, AC-04
Проблема: closure_modules обходит dependency только видов module/subsystem; допустимый check-узел не ставится в очередь. Поэтому транзитивно изменившийся вход не попадает в снимок зависимой проверки (ai-dev-playbook/scripts/checks_inventory.py:273–284).
Воспроизведение: выполнить chain_probe.py из контейнера аудита. Политика содержит check:a → check:b → module:c; после первого успешного запуска изменить src/c/v.txt и выполнить checks plan/run --scope project --mode stale, затем checks release-ready.
Факт: plan показывает обе связи, но a=reused; счётчики a/b меняются с 1/1 на 1/2; release-ready возвращает rc=0 и «готово».
Влияние: изменение объявленной транзитивной зависимости не запускает обязательную проверку; возможна ложная готовность релиза (R-04, R-11, R-16).
Критерий исправления: обходить все допустимые виды узлов, сохраняя циклобезопасность, и учитывать их значимые входы; добавить постоянный E2E с check-цепочкой и assert фактического повторного запуска a после изменения c.
