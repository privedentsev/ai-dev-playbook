Новые проверки PB-056 не меняют старые карточки, доказательства и правила приёмки. Ошибка подготовки останавливает verify до subprocess, не создаёт фиктивный passed-отчёт. Неизвестная команда выявляется до запуска предыдущих команд. Повреждённый/failed/чужой исторический отчёт не запрещает заменяющий прогон. Лимит сравнивается только с успешным неизменным прогоном того же argv в этом корне; рекомендация добавляет 25% запаса, но настройки автоматически не изменяются. История вне стандартных work/verification и docs/archive/tasks/*-evidence не используется для автоматического лимита. Прежний максимум не предсказывает длительность изменённого suite.

Порядок: завершить исправления → зарегистрировать материалы → подготовить in_review и индексы → adopt после изменения комплекта → verify --preflight → self-check → шесть smoke-регрессий → полный unit-tests один раз → CHECK/HANDOFF и lifecycle handoff → verify --audit-ready → независимый аудит. После записи аудиторских материалов повторяется только ранняя проверка, затем проверяется свежесть. Явный --reuse применяется лишь при полном совпадении значимых входов.

Независимый аудит по новым сценариям может потребовать исправлений и повторного прогона. Устранять такие повторы ослаблением независимости или скрытым исключением входов нельзя. Полный прогон не запускают одновременно с редактурой/регистрацией материалов; дорогую проверку после одного и того же отказа повторяют только после устранения причины.
