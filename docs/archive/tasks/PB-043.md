## Задача

### Цель и границы

Одним вызовом читать последнюю HANDOFF и связанные EXEC/CHECK; готовить статус и индекс до финального verify; разделить содержание EXEC/CHECK и сделать последнюю передачу самостоятельной. Схемы, gate и историю существующих карточек не менять; workflow v2 PB-034 не реализуется.

### Контекст

[Требования](../../specs/handoff-context.md). Согласовано при разборе [PB-042](PB-042.md); инженер разрешил весь объём запросом «Давай все это реализуем». Пилот — собственная передача PB-043 и временные проекты.

### Критерии приёмки

- [x] AC-01: card show --handoff одним read-only вызовом возвращает контекст, исходные связанные EXEC/CHECK/HANDOFF и открытые замечания; --json содержит те же записи без нового резюме.
- [x] AC-02: нет передачи, несвежая/неподтверждённая передача, новая работа, inline/external, архив и неподдерживаемый формат показаны честно; прежние --entry/--full/--json совместимы.
- [x] AC-03: порядок подготовки in_review и индекса до verify позволяет выполнить один прогон и зарегистрировать свежую передачу; неуспешный verify и изменения входов не дают ложной готовности.
- [x] AC-04: правила и шаблоны разделяют EXEC/CHECK, требуют самостоятельную последнюю HANDOFF и сохраняют причины решений, ограничения, атрибуцию и доказательства; старые журналы не переписываются.

### План

1. Зафиксировать согласованные требования; draft → ready → in_progress по разрешению инженера.

3. Проверить выбор, свежесть, один verify, отказы и совместимость; обновить self-manifest, подготовить статус/индекс, verify и HANDOFF.
