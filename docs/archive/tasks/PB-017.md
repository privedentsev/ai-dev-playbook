## Приёмка

- [x] Каждый поддерживаемый переход имеет явную цепочку миграций либо отметку, что миграция не нужна; неподдерживаемый переход блокируется до записи.
- [x] Миграции сохраняют пользовательские значения и неизвестные поля; неоднозначные изменения требуют решения, а не скрытой подстановки шаблонов.
- [x] Форматы project.json, resources.json, карточек и AGENTS.md рассмотрены отдельно; история аудитов, ID, статусы и даты сохраняются, неизвестные исторические значения не выдумываются.
- [x] Миграции выполняются на подготовленной копии, их diff включается в план; повторная обработка безопасна, исходный проект не меняется.
- [x] Тесты на старых конфигурациях и карточках подтверждают сохранность данных, пропуск промежуточных версий при наличии цепочки, повторный запуск и отказ на неподдерживаемом формате.

- Поддерживаемые переходы объявляются артефактом в `updates.json → updates_from` («версия»: `{"steps": [...]}`); пустой список — явная отметка «миграция не нужна», необъявленная пара блокируется до записи. - Целевая схема проверяется результатом: после миграций `schema_version` сверяется с `data_format` артефакта (схемы шаблонов), недостижение — ошибка до записи.
- Формат карточек версионируется отпечатком заголовка `templates/task.md`; расхождение с установленным — ручное замечание в плане, авто-перезаписи карточек нет: история аудитов, ID, статусы и даты не трогаются. Расхождение шаблона `templates/AGENTS.md` с корневым `AGENTS.md` — тоже ручное замечание; проектные инструкции сохраняются.
- Миграции вычисляются в памяти для плана и повторно исполняются на подготовленной копии `staged` при `apply`; операции идемпотентны, исходный проект до записи не меняется. Тестовые версии — только fixtures (`fixture_release` в тестах); фиктивных релизов не введено. `adopt`, а не update, — путь для возврата к эталону.

Проверки: `MigrationTest` — шаги применяются с сохранением `custom_field` и `name`, смена схемы без шагов блокируется, смена схемы шагом проходит, замечание при смене формата карточек, идемпотентность `migrate_settings` (двойной прогон). `python3 -m unittest discover -s tests` — 98 тестов OK; `check --ready` — OK.
