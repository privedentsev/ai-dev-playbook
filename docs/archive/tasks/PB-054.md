## Задача

### Цель и границы

По поручению инженера реализовать полный цикл защиты от повторения ошибок PB-051–053: ранний контроль переносимости материалов, безопасная подготовка аудита, проверка конечного дерева при предпросмотре и консервативное повторное использование неизменённого полного verify. Проверка экономной моделью — GPT-6 Luna, затем итоговый разбор основным агентом и штатное закрытие после независимой приёмки.

Не внедряет всю политику task_workflow v2 PB-032–037 и выборочный движок PB-045–050. Legacy-обязательные команды сохраняются; reuse разрешён явно и только для полного свежего набора. Изменённые или неизвестные входы не считаются проверенными. Commit/push/release не входят.

### Контекст

- [Требования](../../specs/audit-material-safety.md).
- [PB-051](PB-051.md): исключённый из staged work/audits, Finder metadata, ошибочная база ссылок сырого снимка, позднее обнаружение при close.
- [PB-052](PB-052.md): версии фикстур и сохранение незатронутых ссылок.
- [PB-053](PB-053.md): исправление конкретного размещения доказательств.
- [План соразмерных проверок](../../plans/proportional-workflow.md); интеграционные уточнения PB-033/PB-034/PB-037 сохраняются в draft.

### Критерии приёмки

- [x] AC-01: проверка материалов до subprocess выявляет существующую ссылку в исключённую из staged область, недоступный после переноса материал и служебные файлы. Предпросмотр регистрации и применение дают согласованный отказ; никакие пользовательские файлы не удаляются.
- [x] AC-02: штатная подготовка аудита создаёт зарегистрированный контейнер в поддерживаемом месте, сырой snapshot в .txt и provenance с исходным путём/SHA-256; preview не меняет проект. Snapshot сохраняет байты, отказ/повтор/закрытая карточка не повреждают историю.
- [x] AC-03: verify --preflight не пишет и не запускает команды; обычный verify выполняет тот же ранний контроль до дорогих проверок. Не требует ещё не созданных отчётов; legacy без documents сохраняет прежний маршрут.
- [x] AC-04: close --dry-run проверяет подготовленное конечное дерево теми же staged-проверками, что применение; gate приёмки сохраняется. Битый сырой Markdown и конфликт будущих ссылок выявляются до записи. Применение заново сверяет входы и сохраняет restore/locks.
- [x] AC-05: явный verify --reuse использует только собственный свежий полный passed-отчёт с совпадающими командами, входами, требованиями/EXEC, policy и средой; failed/timeout/старый формат без необходимых данных/изменённые входы вызывают объяснимый новый прогон. Не исключаются docs или evidence целиком; нет молчаливого сужения обязательных проверок.
- [x] AC-06: постоянные CLI-регрессии воспроизводят ошибки материалов PB-051–053; счётчик подтверждает отсутствие второго запуска при неизменном reuse и новый запуск при содержательной правке. Проверены сохранность, восстановление/гонка, legacy и условная следующая версия без подмены исторических фикстур.
- [x] AC-07: обновлены правила/руководство/CHANGELOG и уточнены PB-033/PB-034/PB-037 без заявления о реализации всего v2; manifest актуален; финальный настроенный verify passed и inputs_unchanged=true, CHECK/HANDOFF зарегистрированы.
- [x] AC-08: независимая проверка GPT-6 Luna сохранена с точной атрибуцией, замечания устранены; приёмка зарегистрирована отдельно от самопроверки, dry-run/close и конечный check проходят, материалы сохраняют байты.

### План

1. Зафиксировать исходные хеши и требования; реализовать общую проверку переносимости и подготовку аудиторских материалов.
2. Подключить read-only preflight и одинаковую проверку будущего дерева preview/apply; добавить консервативный явный reuse полного отчёта.
3. Добавить негативные и сквозные CLI-регрессии, проверить счётчики и сохранность; обновить документы, CHANGELOG, self-manifest.
4. Подготовить статус/индекс/материалы до одного финального verify; записать EXEC/CHECK/HANDOFF.
5. Независимый субагент GPT-6 Luna проверяет результат без исправлений реализации; основной агент разбирает выводы, устраняет замечания при необходимости. После актуальной независимой приёмки выполнить dry-run/close и проверку архива.

### Ресурсы

Python 3/POSIX, локальные временные проекты; исходный checkout dev с существующими незакоммиченными изменениями. policy_revision=2. Инженер явно разрешил экономную модель и полный цикл 2026-10-27; бюджет не задан. Основная модель GPT-6.1 Sol подтверждена инженером; субагент GPT-6 Luna задаётся явно.
