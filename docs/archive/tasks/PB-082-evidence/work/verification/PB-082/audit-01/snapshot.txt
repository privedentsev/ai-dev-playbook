## Задача

### Цель и границы

Сократить проверки локальных правок в ai-dev-playbook через выбор групп по зависимостям. Использовать локальный контур, сохранить полный набор при изменении общего кода и при неизвестной области.

### Контекст

Основа — [пилот PB-064](../archive/tasks/PB-064.md) с уточнениями [PB-073](../archive/tasks/PB-073.md). Workflow v2 уже включён. Инженер одобрил подключение 18 ноября 2026 года. Политика ревизии 1 (`checks-policy.json`) подключена через `setup apply`, операция `20261118-104307-2a6df3d4`. За основу взят [черновик политики](PB-082-evidence/checks-policy.draft.json).

На изолированной копии `setup apply` принял тестовый экземпляр политики. После изменения `tests/test_block_workflow.py` штатные `checks plan` и `checks run` выбрали структурную проверку и 39 тестов приёмки блоков. Обе проверки прошли. После подключения полный набор проверен в основном репозитории.

### Критерии приёмки

- [x] AC-01: Пять групп охватывают 1135 уникальных тестов полного discovery. Шесть повторных запусков через `load_tests` учтены, архивные тесты не входят в набор.
- [x] AC-02: Локальные правки тестов выбирают соответствующую группу, документация выбирает структурную проверку, общий CLI и неизвестная область требуют все группы.
- [x] AC-03: После одобрения политика подключена через `setup apply`, локальный runner выполняет выбранные команды и проверяет фактические unittest ID.

### План

1. Построить группы по полноценному discovery, явно учесть строковые зависимости smoke-набора и общие входы. Проверить выбор и фактический запуск на изолированной копии.
2. После одобрения зафиксировать его в политике, подключить её и создать исходную историю успешных результатов.
3. Зарегистрировать результаты и передачу штатным CLI.

### Ресурсы

Python и стандартный `unittest`. Ревизия 3 для локального контура. Проверка структуры учитывает значимый текст текущей карточки через её проекцию. Служебные изменения карточки и метаданных при передаче проходят структурную проверку lifecycle. Лимит чтения увеличен с 250 МБ до 2 ГБ после отказа подтвердить свежесть проверки структуры при передаче. Группы и правила их выбора сохранены. Группы по discovery: приёмка блоков — 39, выбор проверок — 372, CLI — 164, ядро — 510, verification — 56.

Для нового проекта: с появлением первых тестов описать в политике модули и их пути, дать каждой группе отдельную команду и указать общие зависимости. Перед включением сверить объединение групп с полным сбором тестов и проверить выбор на локальной правке, общем коде и новом пути без владельца. При добавлении модуля обновлять группы и каталог в той же задаче.
