## Задача

### Цель и границы

Устранить A-07 AUDIT-009: эталонный `verifier gate` не должен подтверждать покрытие старым passed после более позднего неуспеха того же кандидата. Согласовать consumer с общей моделью актуального покрытия и доверенной историей. Не переоткрывать архив PB-057–064/PB-073/PB-074/PB-078; код в сессии аудита не менять.

### Контекст

[AUDIT-009](AUDIT-009.md), [протокол audit-04](AUDIT-009-evidence/audit-04/report.md), [реальная проба](AUDIT-009-evidence/audit-04/probe_verifier_gate.py), [подписанные квитанции и CLI-результат](AUDIT-009-evidence/audit-04/verifier-gate.json). Требования [R-11/R-16, AC-05/AC-08/AC-09](../specs/dependency-aware-verification.md), [verification](../../ai-dev-playbook/rules/verification.md).

Воспроизведение: `python3 docs/tasks/AUDIT-009-evidence/audit-04/probe_verifier_gate.py .`. Настоящие verifier subprocess-команды и валидные подписи, один candidate/policy, последовательные passed→failed; записи истории и квитанции не меняются. Task/project checks_gate оставляют probe uncovered; checks_verifier.gate даёт ok=true/covered=1, реальный CLI verifier gate — rc=0. Причина: checks_verifier.py gate() объединяет любые passed из проектных копий вместо выбора актуального доверенного исхода. Стенд capability=local, protected_confirmed=false; реальный OS/CI обход не заявляется.

### Критерии приёмки

- [x] AC-01: Последовательные passed→failed/timeout/blocked одного candidate/policy дают uncovered и ненулевой CLI exit у verifier gate; старый passed не покрывает поздний неуспех. Поведение согласовано с checks_gate для тех же обязательств. Есть реальная subprocess/CLI-регрессия с валидными квитанциями без mock; новый фактический passed восстанавливает покрытие.
- [x] AC-02: Покрытие исходит из актуальной доверенной истории; удаление/переименование проектных копий не воскрешает старый успех и не теряет актуальное доказательство. Проверены candidate/policy/task bindings, TTL/always_run, aggregate/replay/revocation, равные и откатившиеся часы, перекрытие прогонов и непригодная история; безопасные отказы не превращаются в успешное покрытие. Семантика manual и capability/local/protected явно сохранена.
- [x] AC-03: Пройдены адресные checks_gate/trust/e2e и необходимые lifecycle/legacy-регрессии, штатные index/check/verify; документы, self-manifest и передача актуальны. Архивные материалы побайтно сохранены. Исправление передано независимому аудитору; AUDIT-009 не считается принятой автоматически.

### План

1. Прочитать audit-04 и воспроизвести A-07; сопоставить checks_verifier.gate и checks_gate._protected_receipts, границы их CLI-значений ok/protected_confirmed.
2. Согласовать вычисление покрытия через общий контракт без копирования расходящейся логики; добавить реальные поведенческие регрессии и негативные сценарии.
3. Обновить документацию/manifest, выполнить проверки и verify, записать EXEC/CHECK/HANDOFF; независимый аудит исправления, затем повтор AUDIT-009.

### Ресурсы

Python stdlib, временные проекты и trusted home вне репозитория; sandbox-exec вне внешней песочницы. Бюджеты проекта null; реальные затраты проверять до дорогого запуска. Полномочия реальной отдельной OS/CI identity не подтверждены. Зависимости от незавершённой AUDIT-009 нет. Commit/push/release — по отдельному поручению.
