Реализация 2026-09-29 (Devin / SWE-2 High, общий changeset блока PB-014–PB-018):

- `update apply` работает только по сохранённому плану: повторная проверка release_id артефакта и `before_fingerprint` состояния, отсутствие неразрешённых конфликтов и маркера другой операции.
- Подготовленная копия `work/update/<op>/staged` (исключены `.git`, `work`, `__pycache__`, `.DS_Store`, `*.pyc`, `.venv`, `node_modules`): запись релизных файлов, удаления, миграции настроек, новый manifest. Проверки проекта исполняются в копии по **установленной** конфигурации `verification` — команды из артефакта и введённые миграцией не запускаются; неуспех — отказ до записи в проект.
- Резервная копия всех затрагиваемых путей в `backup/` + `backup_index.json`; устойчивый `journal.jsonl` (fsync) фиксирует staged → backup_complete → write/remove → verified → done|failed → restored.
- `work/update/pending.json` — маркер незавершённой операции: обычные команды (check/index/close/verify/init/adopt/update plan|apply) отклоняются до `update restore`; `update status` показывает операцию и хвост журнала.
- Восстановление детерминировано по `backup_index.json` (возврат backed, удаление added), журнал не требуется; идемпотентно — прерывание самого восстановления безопасно. Ошибка записи вызывает автоматическое восстановление в той же операции. `work/update/<op>/restore.py` — автономный скрипт без импорта комплекта: путь восстановления не зависит от повреждённого установленного CLI.
- Итоговая сверка `_verify_final`: VERSION == playbook_version == manifest.playbook_version, хеши ядра совпадают с manifest (kept пропускаются), manifest перечитывается; только после этого `done` и снятие маркера.

Проверки: `UpdateApplyTest` — end-to-end применение (файлы, VERSION, manifest, журнал, бэкап, restore.py), пустой план, повторный план после обновления пуст, keep/release-разрешения, неизвестные файлы сохранены, отказ при падающей staged-проверке без изменения проекта, прохождение staged-проверки, внедрение сбоя записи с автоматическим восстановлением, блокировка команд при pending + `update restore`, автономный restore.py через subprocess. `python3 -m unittest discover -s tests` — 98 тестов OK; `check --ready` — OK.

Непроверенное: прерывание процесса (kill) симулировано маркером и журналом, а не реальным SIGKILL посреди записи; восстановление на другой ОС/ФС не проверялось; независимый аудит не выполнялся.
