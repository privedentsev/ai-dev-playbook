## A-06 — Обратный ход часов скрывает поздний failed

Серьёзность: **P2**. Критерии карточки: AC-01, AC-02, AC-03. Спецификация: R-11/R-16, AC-05/AC-09. Область — local-диагностика; protected-развёртывание этим результатом не заявляется.

Воспроизведение из корня репозитория:

```bash
python3 docs/tasks/AUDIT-009-evidence/audit-03/probe_clock_rollback.py .
```

Проба создаёт временный проект без Git и исполняет настоящие subprocess-команды. Первая команда пишет счётчик 1 и завершается успешно; вторая пишет 2 и завершается с кодом 1. Время первого исполнения берётся из UTC-часов, второму передаётся время на одну секунду раньше через штатный аргумент runner `now`. UUID не подменяются, записи истории не редактируются. Это управляемая модель коррекции системных часов; фактическая коррекция часов машины не выполнялась.

Фактический результат ([JSON](clock-rollback.json)):

1. Project force: passed, run_seq=0.
2. Project force: failed, run_seq=1, finished_at на одну секунду раньше первого.
3. История валидна, corrupt=[]; latest выбирает **passed, run_seq=0**.
4. Gate в областях **task и project возвращает ok=true**, покрывая payment старым успехом.
5. Task stale: **ok=true/reused=1**, число реальных запусков остаётся **2**. Новый успех не получен.

Причина: `checks_select.result_order_key` (строки 435–446) и `_latest_better` (466–478) сравнивают finished_at раньше run_seq. Поэтому доказанный порядок последовательных исполнений используется только при равных часах. Те же сравнения обслуживают индекс, rebuild и gate. При коррекции часов назад более поздний неуспех может быть скрыт старым passed.

Критерий исправления: при конфликте wall clock с доказуемым порядком новых исполнений не разрешать готовность/reuse по старому успеху. Сохранить безопасный порядок legacy, равные часы, индексы/пересборку и восстановление новым фактическим passed. Не заменять проблему безусловным приоритетом sequence без проверки конкурентных запусков и совместимости форматов. Отдельная задача исправления: PB-078.

Чистый набор: **344 теста, OK, 251.125 с** ([полный журнал](checks-tests-clean.log)). Новый plan-only: rc=0, PLAN-ONLY OK, discovery=1113 экземпляров / 1107 уникальных ID, checks-suite=344; command receipt проверен, capability=local; protected release-ready отклонён ([журнал](pilot-plan.log)).
