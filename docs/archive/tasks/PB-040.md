## Задача

### Цель и границы

Единый Markdown-формат карточки для человека и будущего клиентского приложения: версия, журнал с ID, парсер/валидатор, интеграция с lifecycle. Один источник текста без повторов. Клиентское приложение и оптимизация токенов не входят в задачу.

### Контекст

- [Спецификация и согласованный контракт](../../specs/task-card-format.md).
- [PB-038](PB-038.md), [PB-039](PB-039.md): различное оформление журнала и незакрытый чекбокс аудита при наличии acceptance. Чекбокс входил в защищённую handoff-проекцию; менять его после передачи означало менять проверяемые требования.
- [PB-031](../../tasks/PB-031.md) и [PB-034](../../tasks/PB-034.md): отдельная работа над workflow/verification v2. Версия Markdown независима от этой механики; порядок задач не меняется.
- Инженер согласовал формат, сохранение старых карточек без миграции и разрешил реализацию. PB-040 переведена на формат 2 как локальный пилот; остальные существующие карточки не мигрируются.

- Дополнение инженера от 2026-10-24: вернуть визуальные чекбоксы критериев как вычисляемое CLI-отображение результатов журнала. Дополнение реализуется в EXEC-02 по отдельному запросу инженера. Для новой итерации карточка возвращалась в in_progress; HANDOFF-01 и CHECK-01 сохранены как история прежнего объёма и не подтверждают новые AC-08–AC-13. После реализации нужны новые проверки и передача.

### Критерии приёмки

- [x] AC-01: карточка читается как Markdown без приложения; формат версионирован, свободный текст не дублируется в JSON.
- [x] AC-02: парсер извлекает шапку, записи, атрибуцию, критерии и связи; валидатор отклоняет пропуски, дубли ID, неизвестные поля/ссылки и недопустимые значения.
- [x] AC-03: две итерации исправлений и три аудита сохраняют историю; определяются последняя передача, текущий вердикт и открытые находки.
- [x] AC-04: приёмка не дублируется чекбоксом аудита; исторический accepted не обходит актуальную acceptance, freshness и CLI gate.
- [x] AC-05: журнал поддержан проекцией/lifecycle; переданная история и аудит защищены хешами, а изменения требований/реализации требуют новой проверки и передачи.
- [x] AC-06: прежний CLI поддерживает старые карточки; новый просмотр возвращает unsupported и путь Markdown для отсутствующей/неподдерживаемой версии без переписывания архива и доказательств.
- [x] AC-07: шаблон, правила и руководство согласованы; проверены отказы и цикл verify → handoff → возврат → исправление → повторная приёмка → close dry-run → close → reopen на временном проекте.

- [x] AC-08: критерии отображаются как `- [x] AC-01: текст` / `- [ ] AC-02: текст`; галочка означает подтверждение актуальной проверкой, а не независимую приёмку. Источник состояния — журнал и актуальность доказательств, без ручного дублирования в JSON.
- [x] AC-09: пересчёт использует последнюю применимую проверку каждого критерия; passed даёт [x] только при актуальных доказательствах и отсутствии действующей находки. failed/not_run, отсутствие проверки или устаревание подтверждения не оставляют [x]. Открытая находка приоритетнее passed до подтверждения её устранения повторным аудитом.
- [x] AC-10: находки аудита явно ссылаются на затронутые AC-ID. Замечание снимает отметки только затронутых критериев; запись исправления сама по себе не возвращает [x]. После исправления, успешной актуальной проверки и подтверждения устранения аудитором отметка восстанавливается; acceptance остаётся отдельной.
- [x] AC-11: handoff пересчитывает и сохраняет галочки автоматически. Для возврата по аудиту и повторной приёмки предусмотрен согласованный CLI-путь синхронизации; все записи идут через общий gate и восстанавливаемую операцию. Read-only просмотр ничего не исправляет в файле; валидатор сообщает о ручном/устаревшем расхождении и о том, как его исправить через CLI.
- [x] AC-12: только маркеры [ ]/[x] исключаются из проекции требований, ID и текст остаются защищены. Автоматическая синхронизация галочек не делает handoff/acceptance неактуальными; правка требований или истории и устаревание реализации по-прежнему выявляются. Исторические CHECK/HANDOFF/AUDIT не переписываются.
- [x] AC-13: обновлены парсер, шаблон, JSON-просмотр, правила и документация; состояния в Markdown и JSON вычисляются одинаково.
