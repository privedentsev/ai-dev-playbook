## Сценарий обновления

Выбрать локальный артефакт конкретного релиза → проверить состав и установленное состояние → показать diff, миграции и конфликты без записи → разрешить конфликты → пересчитать и проверить план → подготовить копию и выполнить миграции/проверки → применить с резервной копией и журналом → проверить результат и зафиксировать успешную версию.

При изменении входов план устаревает. При сбое должна быть возможность восстановить прежнее состояние; обычная работа с незавершённым обновлением блокируется, восстановление не зависит от исправности заменяемого CLI. Автоматическая загрузка, фоновое обновление, автоматическое слияние конфликтов и выпуск релиза вне первого этапа.

Для старой установки без manifest нужен известный эталон. Одного числа `0.1.0` недостаточно для перехода на `0.0.2`: содержимое проверяется, неоднозначность разрешается явно. Новые изменения не объявляются ретроспективно выпущенными версиями.
