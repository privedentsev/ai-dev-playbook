### Критерии приёмки
- [x] AC-01: Handoff/accept/release-ready используют один selector+coverage; текущие байты сверяются с проверенным candidate. В protected режиме local/поддельные отчёты не закрывают обязательства.

- [x] AC-03: Manual и новые сценарии приёмки не заменяются старым suite; stale передачи, перенос evidence, concurrent edits, restore и запреты внешнего release проверены.
- [x] AC-04: Целевые поведенческие проверки и связанные регрессии пройдены; документация и self-manifest актуальны, EXEC/CHECK/HANDOFF содержат реальные доказательства и ограничения; передача зарегистрирована штатным CLI.

Изменения: `_protected_receipts` — порядок исходов при равных `finished_at` переведён на устойчивую доверенную последовательность запусков: `exec_seq` — позиция receipt-события run-квитанции в журнале verifier для каждого result_digest (построена по всем валидным run-квитанциям дома, включая прежние эпохи — источники aggregate). Aggregate не становится новым исполнением: его исход наследует `exec_seq` исходного run, поэтому при коллизии временных меток aggregate старого passed не отменяет более поздний failed; восстановление — только новым реальным passed. Квитанции вне текущего кандидата/политики валидируются без expect-digest и в исходы не входят; невалидные квитанции прежних эпох отказов не создают. Поведенческая регрессия tests/test_checks_gate.py::test_same_timestamp_aggregate_keeps_failed_latest (passed→failed→aggregate→passed при одном now). Аудитская проба work/verification/PB-062/audit-03/probe.py: after_aggregate ok=False/uncovered=[probe].
