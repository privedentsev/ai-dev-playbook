## Задача

### Цель и границы

Проверить интеграцию всего блока локальными сценариями и согласовать пользовательскую/техническую документацию с реализованным поведением. Самостоятельный независимый аудит собственного кода не выполнять.

### Контекст

[Спецификация](../specs/scoped-file-operations.md): R-01–18; AC-01–10. [Design](../designs/scoped-file-operations.md), [ADR-0005](../adr/0005-scoped-file-operations.md), [план](../plans/scoped-file-operations.md).

Область файлов: Сквозные постоянные тесты, локальные fixtures, docs/architecture.md, docs/code-map.md, user-guide, правила/README, шаблоны и миграции по фактическому результату. Итоговые evidence принадлежат PB-050.

Подготовлено Codex / GPT-6 Astra по поручению инженера 2026-10-26. Выполнение не разрешено. Перед стартом нужны отдельное поручение, актуальное состояние зависимостей и назначение исполнителя. Никаких обязательств по пилоту на реальном большом проекте.

### Критерии приёмки

- [ ] AC-01: Локальный цикл create/index/close/reopen/update/cleanup выполняется с валидными ссылками/sidecar, сохраняя immutable evidence. Реальная рабочая карточка не используется для разрушительных проб.
- [ ] AC-02: Все AC-01–10 спецификации имеют воспроизводимое доказательство; целевые и полный настроенный набор тестов проходят с честным отчётом о timeout/ограничениях, index/check не подменяют поведенческие сценарии.
- [ ] AC-03: Отсутствие полного копирования посторонних данных доказано составом staged и инструментированными I/O; streaming проверен на ограниченных синтетических данных. Реальный большой проект, внешний пилот и числовой SLA не требуются.
- [ ] AC-04: Документация описывает строгую настройку 15, bootstrap, поздний backup, истечение планов, исключения retention, разбор конфликтов и новый контракт update/verify. Действующее/предлагаемое/проверенное не смешаны.
- [ ] AC-05: Старый restore, legacy-переход и совместимость соседних изменений проверены. Self-manifest актуализирован после файлов комплекта; материалы зарегистрированы до финального verify, передача достаточна для AUDIT-008.

### План

1. Собрать локальные сквозные сценарии из требований и проверить взаимодействие engines/cleanup/registry.
2. Обновить постоянные инструкции по фактическому поведению; proposals не объявлять принятыми до независимой приёмки.
3. Стабилизировать входы, зарегистрировать материалы, выполнить проверки и передать блок независимому аудитору.
4. Перед финальным verify зарегистрировать материалы, подготовить in_review и индекс; после изменения файлов комплекта актуализировать self-manifest.
5. Выполнить целевые проверки и `python3 ai-dev-playbook/scripts/playbook.py verify PB-050`. Записать EXEC/CHECK/HANDOFF с командами, результатами и ограничениями; зарегистрировать handoff. Независимая приёмка проводится отдельно.

### Ресурсы

Python 3.10+ и стандартная библиотека; локальные временные проекты. Точная среда и policy_revision фиксируются при старте, бюджет не задан. Исполнитель пока не назначен.

Проверки: Temporary project fixtures без внешних аккаунтов: sidecar/legacy, относительные ссылки, hash-preserved evidence, переход релиза, 16+ операций, утраченная настройка/реестр, SIGKILL/GC. Сохранить команды и наблюдаемые результаты.

Материалы: `docs/tasks/PB-050-evidence/` и зарегистрированные отчёты verify; сейчас материалы реализации не создаются. `index --all`, `check --ready`, `git diff --check` проверяют структуру отдельно от поведения.
