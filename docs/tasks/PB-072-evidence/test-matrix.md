# PB-072 — матрица постоянных проверок

Это план тестов, а не свидетельство их прохождения. Все изменения воспроизводить на временных проектах вне checkout; использовать реальный CLI в subprocess и контроль дерева/SHA-256. Фикстуры должны работать и без Git.

| Сценарий | Требования / AC | Ожидаемый результат |
|---|---|---|
| T-01 Оригинальный runner-каталог плюс ручная копия с зеркальным путём; байты равны | R-02–05 / AC-02,03 | register-material preview/apply рано отклонены; оба material ID/source и общий destination видны; дерево неизменно |
| T-02 Та же раскладка, байты различаются | R-02,05 / AC-03 | Такой же отказ, SHA не разрешает коллизию и не выбирает победителя |
| T-03 Сначала зарегистрирована только копия; handoff автоматически добавляет оригинал | R-03 / AC-02,03 | Отказ до записи handoff/receipts; существующая передача не заменена |
| T-04 Унаследованная коллизия в metadata | R-03,04 / AC-02,03 | preflight и verify до subprocess; счётчик запуска равен нулю; нет pending/нового passed |
| T-05 Разные будущие назначения, одинаковые байты | R-02,06 / AC-03 | Успех без дедупликации; штатные проверки приёмки/закрытия сохранены |
| T-06 Вложенный report.json в каталоге, одинаковое представление одного source, занятый архивный путь | R-02,06 / AC-03 | Реальная коллизия выявлена, законное повторное представление не даёт ложного отказа; занятое назначение отвергнуто |
| T-07 Prepare-audit и независимая задача при чужой коллизии | R-03,04 / AC-02,05 | Свой проектируемый контейнер проверен; чужой owner не блокирует допустимое действие |
| T-08 relocate preview на исходной коллизии | R-07,08 / AC-04,05 | Показаны source/target/hash/link diff, нет записи; проверяется итоговая раскладка, а не только сломанная исходная |
| T-09 relocate apply, ссылка CHECK и raw audit snapshot | R-08,09 / AC-04 | Байты обеих копий сохранены; source и живая цель ссылки обновлены; snapshot/provenance, факты/модель/результаты старых записей неизменны; companion зарегистрирован |
| T-10 Недопустимый перенос: external/shared/архивный owner/каталог/symlink/выход из owner-evidence/занятый target/чужой immutable ref | R-06–08 / AC-04 | Понятный отказ без частичной записи или перезаписи |
| T-11 Gate и изменение source/target после preview, final-check failure | R-10 / AC-05 | Согласованный отказ/rollback; старые байты и receipts сохранены, нет ложного успеха |
| T-12 Прерывание и restore; повтор выполненного переноса | R-10 / AC-05 | Исходное/конечное состояние восстанавливаемо; доказательства не потеряны; повтор не создаёт дубль |
| T-13 Принятая PB-060 после изменения живых ссылок | R-09,12 / AC-04,06 | Старые hashes не подменены; not_current показан честно; новая CHECK/handoff/приёмка требуется по реальным значимым входам |
| T-14 Полный эквивалент PB-060: два отчёта, ранний отказ, preview/apply разнесения, свежие реальные gates, close dry-run и close в fixture | R-11,12 / AC-06 | Нет коллизии, обе архивные копии/история/ссылки сохранены; реальный close ограничен fixture |
| T-15 Inline/external metadata, настроенные нестандартные paths, установленный CLI и обновление комплекта | R-13 / AC-07 | Семантика одинакова; исключения/manifest и полный legacy runner не ослаблены |
| T-16 Правила и пользовательский пример | R-01,13 / AC-01,07 | Оригиналы runner используются через handoff; внешние свидетельства разрешены; ручная правка receipts не предлагается |

Тесты должны сверять фактический owner/check/run ID, а не выбирать результат сортировкой случайных UUID. Для отказов сравнивать дерево до/после; для переноса — SHA-256 исходного и конечного файла, ссылочную целостность и gate. Логи/команды сохранять под PB-072 с реальными исходами, не заменять этот план галочками без проверки.
