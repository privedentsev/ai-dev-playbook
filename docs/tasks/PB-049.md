## Задача

### Цель и границы

Добавить единый retention последних N завершённых операций lifecycle/update, безопасный preview/apply cleanup и явное завершение разбора конфликтов. Не удалять продуктовые данные, evidence и verification.

### Контекст

[Спецификация](../specs/scoped-file-operations.md): R-08,10–13,16–17; AC-06–08. [Design](../designs/scoped-file-operations.md), [ADR-0005](../adr/0005-scoped-file-operations.md), [план](../plans/scoped-file-operations.md).

Область файлов: Новый storage/cleanup модуль, CLI status/cleanup/resolve-conflict, hooks терминального завершения обоих engines, реестр планов и тесты GC.

Подготовлено Codex / GPT-6 Astra по поручению инженера 2026-10-26. Выполнение не разрешено. Перед стартом нужны отдельное поручение, актуальное состояние зависимостей и назначение исполнителя. Никаких обязательств по пилоту на реальном большом проекте.

### Критерии приёмки

- [ ] AC-01: При N=15 после 16+ смешанных completed/restored операций сохранены ровно последние 15 обычных по completed_at/op_id; остальные каталоги с backup/receipt/journal удалены. Staged терминальных операций удаляется сразу.
- [ ] AC-02: Pending, живые процессы, unresolved conflicts, неизвестная/повреждённая legacy-история и зарегистрированные доказательства не удаляются; status объясняет каждую причину и действие. Защищённые записи не вытесняют последние N обычных.
- [ ] AC-03: Cleanup preview не пишет; apply и автоматический cleanup выполняются под shared gate. Revoke плана устойчиво предшествует удалению; сбой между ними не разрешает повтор старого JSON.
- [ ] AC-04: Прерванное удаление возобновляемо, не удаляет чужие/symlink-пути и не создаёт бессрочную очередь tombstones. Cleanup error сохраняет completed предметной операции с предупреждением; rollback предметной операции не запускается.
- [ ] AC-05: Явное подтверждение обработанного конфликта снимает защиту только выбранных путей после сохранения нужных данных; автоматического выбора/перезаписи пользовательской версии нет. Оставшиеся конфликты продолжают защищать операцию.
- [ ] AC-06: Снижение/повышение лимита, повтор cleanup, старые неподтверждённые каталоги, links/evidence и гонки cleanup/apply/restore покрыты. tests, owner-evidence и work/verification неизменны; verify и передача готовы.

### План

1. Реализовать классификацию и read-only status/preview с причинами защиты и оценкой объёма.
2. Подключить устойчивый revoke/delete, безопасное продолжение GC и автоматическую очистку после терминального результата.
3. Добавить явный resolve-conflict, legacy-классификацию и сценарии сохранности доказательств.
4. Перед финальным verify зарегистрировать материалы, подготовить in_review и индекс; после изменения файлов комплекта актуализировать self-manifest.
5. Выполнить целевые проверки и `python3 ai-dev-playbook/scripts/playbook.py verify PB-049`. Записать EXEC/CHECK/HANDOFF с командами, результатами и ограничениями; зарегистрировать handoff. Независимая приёмка проводится отдельно.

### Ресурсы

Python 3.10+ и стандартная библиотека; локальные временные проекты. Точная среда и policy_revision фиксируются при старте, бюджет не задан. Исполнитель пока не назначен.

Проверки: Синтетическая последовательность не менее 16 операций двух engines; pending/foreign lock/conflict/corrupt metadata, symlink, permission denied, SIGKILL во время GC, stale external JSON и защищённые ссылки.

Материалы: `docs/tasks/PB-049-evidence/` и зарегистрированные отчёты verify; сейчас материалы реализации не создаются. `index --all`, `check --ready`, `git diff --check` проверяют структуру отдельно от поведения.
