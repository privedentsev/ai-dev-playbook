## Задача

### Цель и границы

Добавить выборочную подготовку на диске и read-only представление будущего состояния. Адаптировать проверки каталога, карточек/sidecar, ссылок и индексов. Рабочие команды на новый протокол в этой задаче не переключать.

### Контекст

[Спецификация](../specs/scoped-file-operations.md): R-01–04; AC-01–03. [Design](../designs/scoped-file-operations.md), [ADR-0005](../adr/0005-scoped-file-operations.md), [план](../plans/scoped-file-operations.md).

Область файлов: Новый модуль представления проекта/подготовки; documents.py, document_links.py, task_cards.py и проверяющие функции playbook.py/lifecycle.py; постоянные тесты.

Подготовлено Codex / GPT-6 Astra по поручению инженера 2026-10-26. Выполнение не разрешено. Перед стартом нужны отдельное поручение, актуальное состояние зависимостей и назначение исполнителя. Никаких обязательств по пилоту на реальном большом проекте.

### Критерии приёмки

- [ ] AC-01: FutureView читает новые версии из staged, остальные из root; корректно учитывает удаления, переносы, пустые каталоги и относительные ссылки по конечному пути. Сравнение с небольшим физическим ожидаемым деревом даёт одинаковый результат.
- [ ] AC-02: Проверки пар карточка/JSON, метаданных, каталога и индексов обнаруживают дефекты будущего состояния без записи в основной проект; отсутствующие зависимости не маскируются.
- [ ] AC-03: Read-set фиксирует хеши фактически прочитанных байтов файлов, absent paths и состав просмотренных коллекций; внешнее добавление/удаление документа обнаруживается.
- [ ] AC-04: Подготовка не вызывает копирования всего проекта, не создаёт hardlink/symlink на изменяемые оригиналы; синтетические src/media/node_modules вне области операции не копируются. Крупные материалы обрабатываются ограниченными порциями.
- [ ] AC-05: Существующие структурные проверки сохраняют поведение на legacy/inline/external карточках. Предоставлены целевые тесты, verify и свежая передача без утверждения о независимой приёмке.

### План

1. Выделить узкий интерфейс чтения и адаптер реального дерева, определить состав read-set.
2. Реализовать FutureView и подготовленные payload-файлы; перевести проверки на интерфейс.
3. Проверить отсутствующие/новые пути, incoming links, sidecar, состав коллекций и streaming на временных fixtures.
4. Перед финальным verify зарегистрировать материалы, подготовить in_review и индекс; после изменения файлов комплекта актуализировать self-manifest.
5. Выполнить целевые проверки и `python3 ai-dev-playbook/scripts/playbook.py verify PB-045`. Записать EXEC/CHECK/HANDOFF с командами, результатами и ограничениями; зарегистрировать handoff. Независимая приёмка проводится отдельно.

### Ресурсы

Python 3.10+ и стандартная библиотека; локальные временные проекты. Точная среда и policy_revision фиксируются при старте, бюджет не задан. Исполнитель пока не назначен.

Проверки: Небольшие temporary projects с коллизией назначения, перемещённой карточкой, внешней ссылкой, новым файлом коллекции и синтетическим крупным материалом; сравнить с ожидаемым деревом и инструментировать чтения.

Материалы: `docs/tasks/PB-045-evidence/` и зарегистрированные отчёты verify; сейчас материалы реализации не создаются. `index --all`, `check --ready`, `git diff --check` проверяют структуру отдельно от поведения.
