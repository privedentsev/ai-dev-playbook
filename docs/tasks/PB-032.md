## Приёмка

- [ ] always/when_paths/checkpoint вычисляются детерминированно; учитываются baseline, scope, появление/удаление файлов, неоднозначность не позволяет молча пропустить проверку.
- [ ] Coverage требует результата каждого применимого обязательного ID; один passed не скрывает failed/timeout/not_run другого.
- [ ] План/политика/команды/требования — значимые входы; служебные поля отдельно; docs и metadata не исключаются целиком.
- [ ] Независимые checks переиспользуются только при неизменных определениях/входах; неизвестная связь инвалидирует результат.
- [ ] Попытка убрать failed требует инженерского основания и истории; согласование не заменяет реальный результат.
- [ ] Самопроверка и handoff зарегистрированы, независимая приёмка выполнена в отдельной сессии либо инженером перед закрытием.

## Проверки и доказательства

Unit-матрица policy/input/coverage: вложенные паттерны, broad scope, missing baseline, создание/удаление, значимые metadata, отдельные проверки с непересекающимися входами. Предлагаемый файл tests/test_verification_policy.py.

Команды основы: целевые `python3 -m unittest discover -s tests -p '<согласованный файл тестов>' -v`, затем настроенный `python3 ai-dev-playbook/scripts/playbook.py verify PB-032` по действующему на этапе контракту. Перед запуском проверить argv/inputs и готовность служебных данных. Проверить `index --all`, `check --ready`, `git diff --check`; после изменения файлов комплекта выполнить `adopt . --force --apply` до финального прогона. Существующий timeout не обходить скрытым изменением runner: заранее согласовать настройку при необходимости.

Материалы: `docs/tasks/PB-032-evidence/` и зарегистрированные verify-прогоны. Неизменяемые отчёты не переписывать. Структурные проверки не являются доказательством поведения CLI.
