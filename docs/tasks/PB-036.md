## Цель и границы

Обеспечить явное включение v2, init и update существующих установок с сохранением обязательных legacy-команд, пользовательских документов и восстановления.

## Приоритет и зависимости

P2, часть согласованного направления развития. Порядок существующих работ не меняется. Зависимости: PB-035. Карточка создана при планировании, выполнение не разрешено.

## Условия готовности

План/границы согласованы инженером; зависимости завершены; поля/интерфейсы соответствующего этапа однозначны. Исполнитель назначается только при старте. Изменение требований/архитектуры возвращается к соответствующему этапу, не решается скрытым расширением задачи.

## План

1. Согласовать версии/переходы и migration diff.
2. Реализовать explicit opt-in, init/update adapters и отказ старых форматов.
3. Проверить custom paths, conflicts, прерывание и restore на копиях.

## Приёмка

- [ ] До ready инженер согласовал целевую версию локального артефакта и поддерживаемые переходы; они объявлены и проверены.
- [ ] Новая установка валидна; старый проект без подключения v2 работает прежним путём. Переход отдельной карточки/плана явный с историей.
- [ ] Миграция первоначально сохраняет старые обязательные команды как always; сокращение их применимости не выполняется автоматически.
- [ ] Старый CLI/неподдерживаемый формат отказывают, v1-отчёт не считается автоматически v2 coverage. Необъявленный переход отклоняется.
- [ ] Update/restore после прерывания сохраняют пользовательские данные, блокировки, manifest и независимый автономный restore; контрольные точки регрессии не выдают внешнюю интеграцию за реализованную.
- [ ] Самопроверка и handoff зарегистрированы, независимая приёмка выполнена в отдельной сессии либо инженером перед закрытием.

## Проверки и доказательства

Матрица old/new CLI × configs/cards/reports v1/v2, init, dry-run migration, update apply/restore, custom paths, corrupt backup и concurrent lifecycle. Только локальные артефакты/временные проекты.

Команды основы: целевые `python3 -m unittest discover -s tests -p '<согласованный файл тестов>' -v`, затем настроенный `python3 ai-dev-playbook/scripts/playbook.py verify PB-036` по действующему на этапе контракту. Перед запуском проверить argv/inputs и готовность служебных данных. Проверить `index --all`, `check --ready`, `git diff --check`; после изменения файлов комплекта выполнить `adopt . --force --apply` до финального прогона. Существующий timeout не обходить скрытым изменением runner: заранее согласовать настройку при необходимости.

Материалы: `docs/tasks/PB-036-evidence/` и зарегистрированные verify-прогоны. Неизменяемые отчёты не переписывать. Структурные проверки не являются доказательством поведения CLI.
