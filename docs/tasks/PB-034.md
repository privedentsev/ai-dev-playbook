## Цель и границы

Встроить start/route/revise и согласованный handoff в текущий lifecycle engine; закрытие v2 проверяет покрытие и актуальность. Начало работы фиксирует baseline. Восстановление/блокировки сохраняются.

## Приоритет и зависимости

P2, часть согласованного направления развития. Порядок существующих работ не меняется. Зависимости: PB-033. Карточка создана при планировании, выполнение не разрешено.

## Условия готовности

План/границы согласованы инженером; зависимости завершены; поля/интерфейсы соответствующего этапа однозначны. Исполнитель назначается только при старте. Изменение требований/архитектуры возвращается к соответствующему этапу, не решается скрытым расширением задачи.

## План

1. Добавить команды переходов на существующем движке.
2. Подключить v2 coverage/проекции к handoff/accept/close, сохранить v1.
3. Выполнить негативные, конкурентные и fault-injection сценарии.

## Приёмка

- [ ] start/route/revise проверяют допустимость и зависимости, меняют карточку/индекс восстанавливаемо; baseline работает с dirty Git и без Git.
- [ ] handoff учитывает известные текущие/исторические прогоны и материалы, согласованно фиксирует in_review, индекс, результат и coverage.
- [ ] acceptance привязана к конкретной передаче/версии. Новая содержательная правка снимает актуальность; промежуточный просмотр не является acceptance.
- [ ] close требует все актуальные обязательные результаты и приёмку нужной роли; быстрый маршрут — инженер. Служебные переходы не требуют повторных тестов реализации.
- [ ] SIGKILL, повтор, гонки, повреждённые материалы и restore не теряют данные и не создают ложную приёмку; immutable байты сохраняются.
- [ ] Самопроверка и handoff зарегистрированы, независимая приёмка выполнена в отдельной сессии либо инженером перед закрытием.

## Проверки и доказательства

CLI end-to-end с input hashes, счётчиком дорогого теста, переходами и переносом; SIGKILL staged/mid-write, повтор restore, чужая правка и lock contention. Предлагаемые tests/test_task_workflow_lifecycle.py; existing test_close_lifecycle/test_file_operations regression.

Команды основы: целевые `python3 -m unittest discover -s tests -p '<согласованный файл тестов>' -v`, затем настроенный `python3 ai-dev-playbook/scripts/playbook.py verify PB-034` по действующему на этапе контракту. Перед запуском проверить argv/inputs и готовность служебных данных. Проверить `index --all`, `check --ready`, `git diff --check`; после изменения файлов комплекта выполнить `adopt . --force --apply` до финального прогона. Существующий timeout не обходить скрытым изменением runner: заранее согласовать настройку при необходимости.

Материалы: `docs/tasks/PB-034-evidence/` и зарегистрированные verify-прогоны. Неизменяемые отчёты не переписывать. Структурные проверки не являются доказательством поведения CLI.

## Ресурсы

Python 3.10+ и стандартная библиотека, локальные временные проекты без секретов; независимый аудитор отдельной сессией либо инженер. policy_revision — действующая конфигурация на момент старта; бюджет отдельно не согласован. Общие материалы принадлежат AUDIT-007, не архивируются с подзадачей.
