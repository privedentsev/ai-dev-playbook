# ADR-0001: Метаданные принадлежат документу, индексы вычисляются

Статус: принято инженером; реализация не начата.
Дата: 2026-10-01.
Продолжение: по запросу инженера используется как основа [плана](../archive/plans/workflow-and-document-lifecycle.md); внедрение и независимая приёмка не заявлены.
Задача: [PB-020](../archive/tasks/PB-020.md).
Контекст: [спецификация](../specs/workflow-and-document-lifecycle.md), [design](../designs/workflow-and-document-lifecycle.md).

## Проблема

Нужны стабильные связи, состояние документов, владельцы материалов и несколько индексов. Отдельный редактируемый реестр вместе с Markdown создаёт два источника истины; ручные индексы легко расходятся с файлами. Комплект использует Python standard library и работает локально без сервиса.

## Предлагаемое решение

Хранить один явно ограниченный JSON-блок в каждом новом документе. Существующую шапку задач сохранить; дополнительные связи/материалы вынести в их отдельный блок без дублирования статуса и дат. Стабильный ID документа не зависит от пути. Состояние, отношения и владельцы читаются из документов; каталог и индексы вычисляются.

Материалы имеют ровно одного владельца, обратные связи и потребители разрешаются по ID. В индексах допускается только генерируемое представление. Существующие документы без блока остаются legacy и регистрируются по мере работы с ними; глобальная миграция архива не требуется.

## Альтернативы

- Центральный JSON-реестр: проще искать, но любые правки Markdown требуют синхронизации второго файла и создают общую точку конфликтов.
- YAML frontmatter: привычный формат, но полный корректный парсер требует зависимости; самодельный неполный YAML-парсер добавит неоднозначность.
- Только Markdown-заголовки и ссылки: удобны для чтения, но не задают однозначный контракт состояний, владельцев и операций.

## Последствия и ограничения

Блок JSON несколько увеличивает документ, зато читается штатным парсером и переносится вместе с владельцем. Индексы можно восстановить из источников. Нужны строгая схема, понятные ошибки, прицельная регистрация и защита от двойных ID. Метаданные не доказывают, что требования корректны или автор действительно независим: это остаётся предметом приёмки.

Принятие этого ADR ещё не означает внедрение нового формата. После реализации решение остаётся актуальным; при замене новый ADR связывается с этим, а утратившая силу запись архивируется по общему механизму.
