## Контекст

[Спецификация](../specs/dependency-aware-verification.md) требует автоматического выбора тестов без Git, reuse и независимого подтверждения. V2 уже решает часть freshness/coverage, но входы выбираются конфигурацией и локальная история доступна владельцу проекта.

## Предлагаемое решение

1. Расширять v2, не создавать конкурирующий lifecycle: inventory → граф → обязательства → freshness → runner → общий gate.
2. Использовать файловые снимки, а не Git diff как источник истины. Разделить выбор проверок и reuse.
3. Строить граф статическим анализом и явными связями; наблюдения только добавляют зависимости. Unknown расширяет контроль до доказанной границы, вплоть до проекта, в пределах бюджета.
4. Релиз требует полное актуальное покрытие; force выполняет всё заново. Служебный коммит не является изменением тестовых входов.
5. Разделить local и protected: защита от подмены требует внешней границы прав, одобренной политики и проверяемой квитанции. Самоподпись агентом в проекте ничего не гарантирует.
6. Первый встроенный адаптер — Python/unittest; другие технологии через расширяемый контракт и консервативную конфигурацию.

## Альтернативы

- Только инструкции агенту: не подтверждают фактическое выполнение и полноту выбранного набора.
- Все тесты после каждой задачи: дорого, не решает проблему отсутствующих тестов и подмены результатов.
- Только Git diff: не работает без Git, не доказывает свежесть среды и зависимостей.
- Только coverage последнего запуска: пропускает неисполненные ветви и динамические связи.
- Только хеши локальных отчётов: обнаруживают случайную порчу, но владелец может пересчитать их.

## Последствия

Нужны адаптеры, версия графа, тестовый каталог и первоначальная настройка. Неизвестность иногда приводит к дорогому прогону/остановке по бюджету. Защищённое развёртывание требует внешнего управления правами. Автоматика не доказывает бизнес-смысл assertions; ручная/независимая приёмка сохраняется.
