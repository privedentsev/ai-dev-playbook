# Инструкции проекта

Отвечай кратко и по делу. Назначение проекта: см. [продукт](docs/product.md).

1. Определи [режим работы](ai-dev-playbook/rules/workflow.md) из запроса и обозначь его в ответе по этим правилам. Запись задачи и планирование не запускают реализацию.
2. Прочитай карточку текущей задачи и [правила чтения](ai-dev-playbook/rules/context.md), выбери нужные документы через [индекс](docs/index.md). Не читай весь архив и каталог правил.
3. При запуске/возобновлении проверь [карту и команды](ai-dev-playbook/project.json) и [ресурсы](ai-dev-playbook/resources.json).
4. Следуй [правилам задач](ai-dev-playbook/rules/tasks.md), [проверок](ai-dev-playbook/rules/verification.md) и [Git](ai-dev-playbook/rules/git.md).
5. Перед завершением обнови карточку, затронутые документы и запись для передачи работы. Аудит обязательно сохрани по правилам проверок; в итоговом ответе дай ссылку или явно укажи причину невозможности сохранения.

Не выдумывай факты, модели, команды и результаты проверок. Имена исполнителя и модели в записях работы и аудита — точные; неполные данные помечай `(не подтверждено)` по правилам задач; если маркер остаётся к итоговому ответу, прямо спроси у инженера точное название модели. Различай предложения, принятые решения и неизвестное. При `setup_status: needs_review` сначала закончи обследование/настройку; шаблон не доказывает готовность проекта.

Не перезаписывай существующую документацию при внедрении. Не редактируй применённые миграции, не применяй их к общей БД без разрешения. Не сохраняй секреты. Коммиты, push, merge и релизы выполняй в рамках разрешений инженера.

Служебные проверки:

```sh
python3 ai-dev-playbook/scripts/playbook.py index
python3 ai-dev-playbook/scripts/playbook.py check --ready
```

Обновление комплекта — только по локальному артефакту релиза: `update plan <каталог>` (предпросмотр без записи, `--save` сохраняет план), `update apply`, `update restore` после прерывания; установки без manifest — `adopt`. Контракт — `ai-dev-playbook/rules/update.md`. Не применяй обновление без предпросмотра и разрешения инженера.

Команды проверки приложения находятся в `project.json` после обследования. Служебная проверка не заменяет тесты приложения.

Начинай чтение задачи с `python3 ai-dev-playbook/scripts/playbook.py card show <ID>`; передача с исходными EXEC/CHECK — `--handoff`, отдельная запись — `--entry <ID>`, полная история — `--full`. До финального verify подготовь статус и индекс по общим правилам проверок; сам статус не подтверждает передачу. Для неподдерживаемого формата открой указанный Markdown. Общий порядок для всех агентов описан в `ai-dev-playbook/rules/context.md`.

Для явно включённого workflow v2 выбирай [quick](ai-dev-playbook/rules/workflow.md#быстрый-маршрут-и-итерации-workflow-v2) только при ясной локальной цели и низком риске без нового поведения. Обоснуй маршрут и конкретные проверки до реализации. Уточнения сохраняют ID; просмотр не означает приёмку. При расширении риска повысь маршрут и дополни ту же карточку. Quick принимает инженер явно; регистрация приёмки/закрытие — по его поручению. В v2 handoff согласованно меняет статус/индекс; ручная подготовка до verify выше относится к legacy. Не включай v2 автоматически.
