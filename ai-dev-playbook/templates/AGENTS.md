# Инструкции проекта

Отвечай кратко и по делу. Назначение проекта: см. [продукт](docs/product.md).

1. Определи [режим работы](ai-dev-playbook/rules/workflow.md) из запроса и обозначь его в ответе по этим правилам. Запись задачи и планирование не запускают реализацию.
2. Прочитай карточку текущей задачи и [правила чтения](ai-dev-playbook/rules/context.md), выбери нужные документы через [индекс](docs/index.md). Не читай весь архив и каталог правил.
3. При запуске/возобновлении проверь [карту и команды](ai-dev-playbook/project.json) и [ресурсы](ai-dev-playbook/resources.json).
4. Следуй [правилам задач](ai-dev-playbook/rules/tasks.md), [проверок](ai-dev-playbook/rules/verification.md) и [Git](ai-dev-playbook/rules/git.md).
5. Перед завершением обнови карточку, затронутые документы и запись для передачи работы. Аудит обязательно сохрани по правилам проверок; в итоговом ответе дай ссылку или явно укажи причину невозможности сохранения.

Не выдумывай факты, модели, команды и результаты проверок. Различай предложения, принятые решения и неизвестное. При `setup_status: needs_review` сначала закончи обследование/настройку; шаблон не доказывает готовность проекта.

Не перезаписывай существующую документацию при внедрении. Не редактируй применённые миграции, не применяй их к общей БД без разрешения. Не сохраняй секреты. Коммиты, push, merge и релизы выполняй в рамках разрешений инженера.

Служебные проверки:

```sh
python3 ai-dev-playbook/scripts/playbook.py index
python3 ai-dev-playbook/scripts/playbook.py check --ready
```

Команды проверки приложения находятся в `project.json` после обследования. Служебная проверка не заменяет тесты приложения.
