# Рабочий комплект

- `rules/` — переносимые правила. Проектные факты хранятся в `docs/`.
- `project.json` — реальные пути, команды, разрешения Git и версия внедрения.
- `resources.json` — доступность инструментов, модели, бюджеты, снимки квот.
- `templates/` — исходники новых документов; это не факты о проекте.
- `scripts/playbook.py` — установка, проверка, индекс задач, запуск `verify TASK-ID`.
- `scripts/verification.py` — исполнение проверок на POSIX и JSON-отчёты.
- `VERSION` — версия комплекта. Не менять при обычном изменении проекта.

Обновления правил переносить через diff. Настройки и заполненные документы не заменять шаблонами. В прототипе обновление ручное: сравнить версии, адаптировать изменения, проверить, затем обновить `playbook_version` в `project.json`.

Для `verify` добавьте в project.json блок `verification` с `inputs` (пути исходников/тестов) и `checks`: список объектов `id`, `argv` (массив строк), `timeout_seconds` (положительное число). Объявите все файлы, от которых зависит проверка. Проектные конфиги и карточка добавляются автоматически. Строки `commands` не исполняются. Команда `verify TASK-ID --dry-run` показывает план без записи; обычный запуск сохраняет логи и `report.json` в `work/verification/`. Это локальное исполнение доверенных программ с текущими правами, без sandbox и без изменения статуса задачи.
