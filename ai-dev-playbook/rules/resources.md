# Ресурсы агентов

`resources.json` редактирует инженер или агент по его указанию. При изменении политики увеличивать `policy_revision`, менять `updated_at`. Это отдельная версия от версии playbook.

- `tools`: инструменты и доступность (`reported`, `confirmed`, `unavailable`, `unknown`); `variant` уточняет облачный/локальный вариант.
- `models`: записи с точным `id`, `availability`, `roles` (например, implementation/review/architecture), `fallbacks` (ID допустимых моделей). Не угадывать названия и возможности.
- `budgets`: `per_task` и `verification_reserve`; значение — `null` либо объект `amount`, `unit` (tokens/USD/minutes), `scope`. Нельзя сравнивать бюджеты с разными единицами.
- `quota_snapshots`: объекты `tool`, `model` (может быть null для общей квоты), `remaining`, `unit`, `checked_at`, `expires_at`, `source`. Даты со временем и часовым поясом. Истёкший снимок не считать действующим остатком.
- `null` / пустой список означает неизвестно, а не нулевой расход или безлимит.

## Выбор

1. Прочитать текущую политику при запуске/возобновлении.
2. Сопоставить требования задачи с доступными моделями и проверенным остатком, если установлен жёсткий бюджет.
3. Учитывать резерв для приёмки; для независимого аудита назначить отдельного проверяющего.
4. Использовать текущего явно выбранного инженером исполнителя в пределах разрешения. Если обязательный ресурс неизвестен/недоступен — уточнить либо применить разрешённую замену.
5. Зафиксировать исполнителя, известную модель и `policy_revision` в карточке. Не переписывать исполнителей прошлых этапов.

На контрольной точке перечитать версию. При изменении доступности или бюджета пересмотреть оставшийся план; не бросать незаписанную работу. Новые и возобновляемые задачи используют новую политику.

JSON не переключает модель и не измеряет расход. Прототип не получает квоты через API и не обеспечивает жёсткий лимит. Не выдавать предполагаемый остаток за измеренный. Без интеграции значения обновляются вручную.
